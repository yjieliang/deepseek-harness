# 引擎底层机制（下）：资源、运行时、线程与工具链

> **本文件是「要验的清单」，不是「已验的结论」。** 凡未在本机跑出 A 级证据的行，裁决单里不得当事实引用。
> 状态列：【规则类】= 语言/工程纪律，不需实测即可要求；【待实测】= 引擎行为，必须 A 级证据。
> 上集（对象与内存、帧与通知、SceneTree 生命周期、信号与 Callable）见 `engine-lifecycle.md`。

## 1. 资源加载与缓存

| 机制 | 要追问的不变量 | 常见错解 | 探针怎么测 | 状态 |
|---|---|---|---|---|
| `load` vs `preload` | 前者运行时按路径查缓存，后者编译期常量 | 热路径里反复 `load()` 同一资源 | 循环 `load` 后看资源实例是否同一引用 | 待实测 |
| 缓存与驻留 | 已加载资源在引用归零后的驻留策略 | 以为卸载场景就释放了资源 | 加载/释放后打印 `Performance` 内存监视器 | 待实测 |
| 线程加载 | 大资源走线程请求，主线程轮询取回 | 主线程同步加载大资源造成卡帧 | 对比同步/线程加载的帧时间 | 待实测 |
| 资源复用 | 资源是共享实例，改一处影响所有使用者 | 直接改共享 Resource 的属性 | 两个节点引用同一 `.tres`，改一个看另一个 | 待实测 |
| `duplicate` | 浅/深复制的边界（嵌套子资源） | 只浅复制就改嵌套资源 | 改副本的嵌套子资源，看原资源是否被污染 | 待实测 |
| 自定义 Resource | 需要可导出字段与安全默认值 | `_init` 里留未初始化字段 | 新建资源实例直接读字段 | 待实测 |

## 2. GDScript 运行时

| 机制 | 要追问的不变量 | 常见错解 | 探针怎么测 | 状态 |
|---|---|---|---|---|
| 静态类型 | 标注类型影响派发路径与警告 | 热路径全用未标注 `Variant` | 同一算法带/不带类型标注各跑 N 次计时 | 待实测 |
| typed `Array` | `Array[T]` 与无类型数组的存取差异 | 大数组用无类型 | 同上，计时对比 | 待实测 |
| `StringName` | 频繁比较的字符串应改驻留名 | 热路径拿字符串字面量比较 | 字符串 vs `&"name"` 字典查找计时 | 待实测 |
| `Dictionary` 查找 | 键查找与数组线性查找的量级差异 | 用 `Array.find()` 做大表查找 | 两种结构各跑 N 次计时 | 待实测 |
| 闭包/lambda | 捕获会延长被捕获对象寿命 | 长生命周期闭包捕获节点 | 捕获后释放节点，看对象数是否下降 | 待实测 |
| 编辑器脚本 | `@tool` 脚本在编辑器里也执行 | 无 `Engine.is_editor_hint()` 防护就改场景 | 编辑器内打开场景看是否被改 | 规则类 |

## 3. 线程与并发

| 机制 | 要追问的不变量 | 常见错解 | 探针怎么测 | 状态 |
|---|---|---|---|---|
| 场景树跨线程 | **后台线程不得访问场景树**（上游明示的硬禁忌） | 工作线程里 `add_child` / 改节点属性 | 在工作线程里尝试访问，看报错 | 待实测 |
| 回主线程 | 线程安全的 API 调用要走延迟调用 | 直接在工作线程里发信号改 UI | 对比 `call_deferred` 与直接调用的结果 | 待实测 |
| 线程池 | 任务提交与等待的阻塞语义 | 在主线程里等线程池任务（等于没并行） | 主线程等待前后的帧时间 | 待实测 |
| 互斥与竞态 | 共享数据要锁；引擎对象引用跨线程不自动安全 | 只用锁保护一半数据 | 构造竞态跑多次看是否复现 | 待实测 |

## 4. 脚本、导出与版本一致性

| 机制 | 要追问的不变量 | 常见错解 | 探针怎么测 | 状态 |
|---|---|---|---|---|
| `@export` / `@onready` | 求值时机不同；`@onready` 在进入树后才可用 | 在 `_init` 里用 `@onready` 变量 | 在 `_init` 读该变量看是否为 null | 待实测 |
| `uid://` | 资源引用与路径引用的差异、跨机器可移植性 | 手工改 `.uid`/`.import` | 改动资源路径后看引用是否断 | 待实测 |
| 导出模板 | 模板版本与引擎版本不一致会失败或行为异常 | 用旧模板导新引擎工程 | 比对引擎版本与模板版本字符串 | 规则类 |
| `.godot/` 与导入缓存 | 生成物不入版本管理、不手改 | 手改导入缓存、把 `.godot/` 提交 | 检查版本管理清单 | 规则类 |
| 版本差异 | 4.3 之后的默认值变更（物理引擎、渲染后端、着色器纹理类型等） | 用旧记忆写新版本代码 | 见 `version-matrix.md`，逐条本机核对 | 待实测 |

## 5. GDExtension 与 C#

| 机制 | 要追问的不变量 | 常见错解 | 探针怎么测 | 状态 |
|---|---|---|---|---|
| ABI | 二进制**不跨小版本 ABI 兼容**，升引擎须重编译 | 拿旧编译产物直接换引擎 | 换引擎后加载扩展看是否失败 | 待实测 |
| 边界开销 | 每次进出原生边界的调用都有成本 | 紧循环里频繁回调引擎 API | 边界调用 N 次的计时 | 待实测 |
| 类注册 | 未注册的类与函数对脚本不可见 | 只写实现、忘注册 | 从脚本侧调用看是否解析到 | 待实测 |
| C# 节点类 | 缺 `partial` 时源生成器**静默失败** | 漏写 `partial` | 编译后看信号/导出是否可用 | 规则类 |
| C# 异步 | 用引擎计时器而非线程睡眠类 API | 用 `Task.Delay()` 破坏帧同步 | 两种等待各跑一次比对调用帧 | 规则类 |
| 原生内存 | 引擎对象要用引擎的引用包装而非裸指针 | 裸指针持有引擎对象 | 释放后访问看是否崩溃 | 待实测 |
