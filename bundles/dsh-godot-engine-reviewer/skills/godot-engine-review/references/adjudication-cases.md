# 判定样例（Adjudication Cases）

> 样例来自**真实实测**（2026-10-09，Windows + `4.7.2-stable.official.ed1daf0bf`）。照抄的是**推理形状**，不是结论本身。
> 每条样例都演示：原子化 → 补齐五元组 → 取到哪一级证据 → 判定 → 为什么不是另外两种判定。

## 样例 1 — 判「成立」

**主张**：「Godot 4.4 起 `FileAccess.store_*` 由 void 改为返回 bool。」

- 原子化：一条（版本 + 行为）。
- 五元组：版本 `4.7.2-stable`（本机实测版本，比主张的 4.4 更新）；平台 Windows；复现步骤＝探针 `_case()`；最小示例＝探针工程；观测输出＝原始 `PROBE/` 行。
- 证据：
  - `A: PROBE/store_string_return_type=bool`、`PROBE/store_string_return_value=true`（4.7.2-stable @ Windows，探针目录 `<TEMP>/godot-engine-probes/2026-10-09-fileaccess-store/`）
  - `B: 官方文档 4.x FileAccess.store_string 返回 bool`
  - `C: godot-skills@d52b934 references/breaking-changes.md`（4.3→4.4 段，上游标注 VERIFY）
- **判定：成立**（范围限定为「4.4 及以后，含实测的 4.7.2」）。
- 为什么不是「证据不足」：A 级证据直接复现了行为，缺口只在 4.4–4.6 未逐一跑，但主张说的是「4.4 起」，向下覆盖成立。
- 排除了什么替代解释：排除「返回值只是打印用的字符串」——`type_string(typeof(returned))` 是 `bool`，不是 `String`；也排除「写入失败仍返回真」的误读方向（本次写入后 `read_back=hello` 一致）。

**可复用的推理形状**：breaking change 类主张 → 在本机（通常比主张版本更新）跑最小复现 → 若行为一致，判成立并把范围写到实测版本；若行为相反，判不成立并给出该版本号。

## 样例 2 — 判「不成立」（范围过宽）

**主张**：「这个沙箱里 headless 跑 Godot 根本写不了文件，所以探针拿不到证据。」

- 五元组：版本/平台齐全（4.7.2-stable @ Windows）。
- 反例（A 级）：同一沙箱、同一次运行里，`res://probe-output.txt` 写入成功并读回内容（`PROBE/read_back=hello`，dump 文件 175 字节）。
- 现象归因：确实有 `ERROR: Could not create directory: 'user://logs'`，但那是 **`user://`（`%APPDATA%\Godot`）在该沙箱下不可写**，不是「写文件不可用」。
- **判定：不成立**（作为普适断言）；正确表述是「`user://` 路径在该沙箱下不可写，`res://` 可写」。
- 为什么不是「证据不足」：反例已实测到，不需要更多证据。

**可复用的推理形状**：把「某路径失败」推广成「某能力不可用」是典型范围越界。判定时把主张缩到它真正证明的范围（这里是路径级），而不是整体推翻——推翻的只是那个过宽的措辞。

## 样例 3 — 判「不成立」（工具链事实）

**主张**：「用 PowerShell 重定向就能把引擎输出存成文件当证据：`& $engine ... *> out.txt`。」

- 反例（A 级）：`*>` 落文件得 **0 字节**；`2>&1` 时终端完全无输出；同样的命令在 `cmd /c "... > out.txt 2>&1"` 下有 618 字节。
- 归因：本机沙箱不允许原生进程输出经 PowerShell 管道。
- **判定：不成立**。替代方案：裸调用（终端直接可见）或 `cmd` 重定向 + `Get-Content -Encoding utf8` 读回；探针本身写 `probe-output.txt` 最稳。

**可复用的推理形状**：工具链主张也要判「成立/不成立」，而且必须实测——「一般都能这么干」在受限环境里经常不成立。

## 样例 4 — 判「证据不足」

**主张**：「每帧 `get_node()` 一定造成明显掉帧。」

- 缺项：**观测输出**（没有任何帧时间/耗时读数）、复现步骤、样本量。
- 已有线索：`C: godot-skills@d52b934 references/deprecated-apis.md` 把它列为 deprecated pattern，理由是每帧路径查找——**这是设计建议，不是量化结论**。
- **判定：证据不足**（既不能判成立，也不能判不成立）。
- 补齐条件：在目标版本/平台上跑对比探针——同一节点用 `@onready` 缓存引用 vs 每帧 `get_node()`，各跑 N 次、给 P50/P95 耗时与帧时间差值，附原始输出。
- 补齐前结论写法：`证据不足，不作为通过依据；若实施方主张「无所谓」，需先补量化。`

**可复用的推理形状**：**反模式清单只提供线索，不提供量化结论**。清单说「这是反模式」≠「它的代价在你的场景里显著」。代价要测出来才能写进收益列。

## 判定时的常见错误（自查）

| 错误 | 纠正 |
|---|---|
| 把清单/文档条目直接写成「事实」 | C 级只是线索，判定前补 A 或 B 级 |
| 因为主张来自资深的人/权威文档就不拆原子 | 拆原子，逐条判；权威也可能说错版本 |
| 「证据不足」写成「基本成立」 | 三态之外没有第四态 |
| 判「不成立」却只给「感觉不对」 | 必须给反例或可执行的反证路径 |
| 用 4.6 的结论覆盖 4.7（或反之） | 版本越界＝证据不足，或补测 |
| 把环境噪音（如根证书读取失败）当发现 | 噪音不是发现；先归因到环境，再决定要不要记 |
