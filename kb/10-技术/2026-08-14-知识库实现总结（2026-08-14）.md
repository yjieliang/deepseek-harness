# 知识库实现总结（2026-08-14）

## 目标

把 DeepSeek Harness（Web GUI + 智能体）打造成个人知识库：搜索收集 → AI 整理 → 快速取用，形成「回答即沉淀」闭环。

## 产出清单

### 1. 设计方案

- `kb/DESIGN.md`：完整九章方案 —— 使用场景 / 总体架构 / 存储设计（纯 Markdown + 索引）/ 功能设计（收集/整理/检索/入口/面板/编辑/图片/双链/配置/成本遥测）/ 智能体协作流程 / 三阶段实施路线 / 安全防护 / 风险权衡
- 经外部评审报告核验：路径沙箱、渲染 sanitize、外部请求护栏、expectVersion 并发协议、MVP 拆分 1a/1b/1c 等均已落实

### 2. 已实现功能（动态插件 kbx-3，pkg-4 → pkg-19）

**Host 工具（14 个）**：

- 核心：`kb_search`（2-gram 倒排索引，中英文）/ `kb_add` / `kb_get`（含双链反链）/ `kb_update`（expectVersion 冲突保护）/ `kb_move`（移动即改 status）/ `kb_delete`（进回收站）
- 知识网络：`kb_links`（出链/反链）
- 整理：`kb_tags`（标签增删改查）/ `kb_organize`（规则版整理报告：积压/重复/过期）/ `kb_stats` / `kb_archive`（过期冷归档，dry-run 先行）
- 文件：`kb_images`（图片索引与孤儿检测）/ `kb_import`（批量导入）/ `kb_export`（导出）/ `kb_clip`（URL 剪藏，web 优先 + curl 回退 + 降级）

**GUI 面板（Client）**：

- 入口：侧栏底部「📚 知识库」按钮 + 会话头部快捷图标（`sidebar.footer.action` / `conversation.session.header.utilities`）
- 面板（`shell.overlay` 浮层）：搜索（清空回退全量）/ 目录·状态过滤 chips / 文档列表 / 分屏编辑器（源码+预览）/ 新建（模板）/ 移动 / 删除（回收站）/ 批量选择与批量操作 / 回收站视图（恢复/彻底删除）/ 图片渲染（HTTP 直连）/ 反链展示

**基础设施**：

- 路径沙箱（resolve + contains 校验，防穿越/符号链接逃逸）
- 原子写盘（fs.writeText 临时文件+rename）+ FsVersion 乐观锁
- `_meta/index.json`（schemaVersion v3）+ `_meta/images.json`
- `kb/templates/` 4 个模板（普通笔记/读书笔记/会议纪要/代码片段）
- 常驻预设「知识库模式」（`C:\Users\v_yjieliang\.dsh\.agent-presets\knowledge-base\`，kb-plugin.mjs，挂载校验通过）—— 跨重启、跨会话可用

## 关键技术决策

| 决策 | 原因 |
|---|---|
| 纯 Markdown 存储 + 可重建索引 | 可移植、无锁定、git 可版本化 |
| 2-gram 字符倒排索引 | 免分词库覆盖中文，MVP 检索即时可用 |
| 图片走 webServer HTTP 路由（`/dsh-kb`） | 私有 RPC 对 67KB base64 有负载截断 → 浏览器原生加载+缓存 |
| expectVersion 用 fs 的 FsVersion 令牌 | replaceIfVersion 守卫写 = 现成乐观锁 |
| 动态工具必须 `harness.defineTool()` 包装 | registerTool 强制要求规范化定义 |
| 预设插件用 `.mjs`（ESM） | loader 以 require() 加载入口，.js/.ts 触发 require(esm) 循环错误 |

## 踩坑记录（问题 → 根因 → 修复）

1. **kb_search 英文检索为空** → 查询按整词、索引按 2-gram 粒度不一致 → 查询侧拆 2-gram（pkg-5）
2. **kb_move/kb_delete 失败** → 目标目录不存在 + shell stderr 是对象 → 自动建目录 + outText 提取（pkg-7）
3. **图片不显示** → ① 面板缓存旧内容 → 重开刷新；② base64 dataUrl 超 RPC 负载被截断 → HTTP 路由直连（pkg-13）
4. **搜索框清空后列表消失** → 空查询走 kb.search 返回空 → 空查询回退 kb.list（pkg-10）
5. **知识库入口消失** → Host-only 更新包卸载了 Client 半区 → 恢复完整 Client 包（pkg-18），教训：动态插件更新是全包替换
6. **kb_clip 无法抓正文** → 部署的 web fetch provider 未启用（tool-web fetch:false）+ 沙箱拦截 curl → 按设计降级为「仅存 URL+标题」

## 现状与已知限制

- 动态插件不跨进程重启：kb/ 数据完好，重启后需重新激活或改用「知识库模式」预设
- URL 剪藏正文提取在当前部署受限（web fetch 未启用）
- 语义检索（Phase 3）未实现：需本地 embedding 模型 + helper 进程基建，设计为自动下载、零手工安装
- kb_organize 为规则版（相似度/状态启发式），非 LLM 深度分类

## 后续方向

- 预设内启用 web fetch 使剪藏抓正文
- git 自动提交 hook、敏感信息检查、图片压缩/缩略图
