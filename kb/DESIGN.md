# 个人知识库设计方案

> 目标：把当前 DeepSeek Harness（Web GUI + 智能体）打造成个人知识库，实现「搜索收集 → AI 整理 → 快速取用」的闭环。
> 内容定位：混合型 —— 网页剪藏、导入文档、学习笔记、代码片段都收，按主题归档。

---

## 1. 使用场景

| 场景 | 用户说法 | 系统行为 |
|---|---|---|
| 收集 | 「帮我搜一下 X，存进知识库」 | 网页搜索 → 生成笔记（标题/摘要/来源/要点）→ 放入收集箱 |
| 收集 | 「把这篇文档 / 这段话记下来」 | 导入文件或粘贴文本 → 转 Markdown → 存入收集箱 |
| 取用 | 「知识库里关于 Y 有什么？」 | 自动检索知识库 → 引用相关文档作答 |
| 参考 | 「写方案时参考一下之前存的 Z」 | 检索相关文档，注入回答上下文，标注引用来源 |
| 管理 | 浏览 / 搜索 / 编辑 / 删除文档 | GUI 知识库面板完成 |
| 整理 | 「帮我整理一下知识库」 | AI 建议分类、补摘要、检测重复、归档冷内容 |

核心闭环：**回答即沉淀** —— 每次有价值的问答，都可以一句话存进知识库，下次随时取用。

---

## 2. 总体架构

```
┌────────────────────────────────────────────────┐
│ Web GUI（Client 插件）                          │
│  入口：侧栏「知识库」按钮 · 会话头部快捷按钮    │
│  面板：搜索框 · 目录树 · 标签 · 文档列表        │
│  编辑器：Markdown 源码+预览分屏 · 自动保存      │
│  图片：![[路径]] 嵌入 · 粘贴选目录              │
└───────────────────┬────────────────────────────┘
                    │ 私有 JSON 方法（Client → Host）
┌───────────────────▼────────────────────────────┐
│ Host 插件（智能体运行时）                      │
│  知识库工具：kb_search / kb_add / kb_list      │
│              kb_update / kb_delete / kb_organize│
│  检索引擎：内存倒排索引（2-gram）+ 相关度排序   │
│  安全层：路径沙箱 · 渲染 sanitize · 请求护栏    │
│  并发控制：expectVersion 乐观锁（双通道统一）   │
│  文档读写：Markdown 解析 / 生成 / 元数据索引    │
└───────────────────┬────────────────────────────┘
                    │ 文件系统读写
┌───────────────────▼────────────────────────────┐
│ 存储层：纯 Markdown 文件 + JSON 元数据索引      │
│ 默认根目录：<工作区>/kb/（路径可配置）          │
└────────────────────────────────────────────────┘
```

设计要点：

- **存储与运行时解耦**：所有知识都以普通 `.md` 文件存在磁盘上，插件只是「读写 + 检索 + 界面」的壳。即使插件停用，知识完好无损。
- **AI 与界面双通道**：智能体通过工具读写知识库（对话中自动检索）；人通过 GUI 面板管理（手动浏览编辑）。
- **无数据库锁定**：不引入专有数据库，任何文本编辑器、git、笔记软件都能直接打开知识库。

## 3. 存储设计

### 3.1 目录结构

```
kb/
├── 00-inbox/            # 收集箱：此路径下文档 status=inbox（状态由路径推导）
├── 10-技术/             # 主题目录（按需增减，如：10-技术/11-AI/ 12-前端/）
├── 20-学习笔记/
├── 30-工作文档/
├── 40-生活通用/
├── 90-归档/             # 冷数据：此路径下文档 status=archived（状态由路径推导）
├── .trash/              # 回收站：删除的文档/图片暂存，可恢复或彻底清除
├── templates/           # 文档模板（读书笔记 / 会议纪要 / 代码片段等）
├── _meta/
│   ├── index.json       # 全库元数据索引（带 schemaVersion，原子写，可重建）
│   ├── images.json      # 图片清单：文件名 → 路径、被哪些文档引用（支撑 ![[文件名]] 直查）
│   └── tags.json        # 标签体系
├── DESIGN.md            # 本设计文档
└── README.md            # 使用说明
```

### 3.2 文件命名与元数据

- 文件名：`YYYY-MM-DD-短横线标题.md`，如 `2026-01-05-rag-检索增强生成.md`；标题允许中文，自动剔除 `/ \ : * ? " < > |` 等非法字符，重复时加序号后缀
- 每篇文档头部带 YAML frontmatter（仅扁平 key-value 与行内数组，解析统一在 Host 端，规避多行字符串/嵌套的边界复杂度）：

```yaml
---
title: 检索增强生成（RAG）入门
aliases: [RAG, 检索增强]        # 别名/同义词，参与检索，提升召回
tags: [AI, RAG, LLM]
source: https://example.com/rag-intro   # 原始来源（网页/文件）
summary: RAG 通过检索外部知识增强大模型回答，缓解幻觉。   # AI 生成的一句话摘要
created: 2026-01-05
updated: 2026-01-06
---
正文（Markdown）……
```

> `status` 不存 frontmatter —— **状态由路径推导**（单一事实源）：`00-inbox/` 下即 inbox、`90-归档/` 下即 archived、其余目录即 filed，移动文件即改状态，杜绝双源腐化。

### 3.3 为什么用纯 Markdown

| 优点 | 说明 |
|---|---|
| 可移植 | 任何工具可读，不绑定本系统 |
| 可版本管理 | 直接放进 git，历史可追溯 |
| 无锁定 | 不用专有数据库，坏了也能恢复 |
| AI 友好 | 智能体读写 Markdown 零成本 |

### 3.4 索引与并发一致性

- **索引文件**：`index.json` / `images.json` 带 `schemaVersion`，写入一律原子替换（临时文件 + rename）；启动时校验版本并抽样核对文档 mtime，不一致自动全量重建
- **演进预留**：index.json 预留 `embeddingRef`（指向 `_meta/vectors/` 分片），Phase 3 语义检索无需全库重建索引
- **增量更新**：索引随每次增删改增量更新；`images.json` 全量重建仅在启动校验失败或文件缺失时触发
- **变更事件流**：索引更新层发布 `doc.created / doc.updated / doc.deleted / doc.moved` 事件，供反链刷新、git 自动提交（Phase 2）等 hook 订阅
- **并发控制（双通道统一）**：GUI 自动保存与 agent `kb_update` 都走 Host 同一写路径，携带 `expectVersion`（mtime+size 哈希）乐观锁；版本不匹配返回冲突 —— GUI 提示合并/重载，agent 重读后重试，杜绝静默覆盖
- **写放大控制**：MVP 单文件索引 + 原子替换足够（个人库量级）；文档 >5,000 篇时按目录分片（Phase 2 阈值触发）

## 4. 功能设计

### 4.1 收集（怎么进）

| 方式 | 操作 | 落点 |
|---|---|---|
| 网页搜索 | 「搜 X 并存进知识库」 | 自动生成笔记 → `00-inbox/` |
| URL 剪藏 | 给一个链接 | 抓取正文 → Markdown 化 → `00-inbox/` |
| 文件导入 | 上传 `.md` / `.txt`（后续支持 docx/pdf） | 转 Markdown → `00-inbox/` |
| 对话沉淀 | 「把刚才的结论记下来」 | 生成要点笔记 → `00-inbox/` |

入库时自动做：拟标题、写一句话摘要、记录来源与时间。

**URL 剪藏护栏**（外部请求 guardrail）：超时 ≤10s、重试 ≤2 次、响应体 ≤5MB、仅允许 http/https、拒绝 `file://` 与私有网段（防 SSRF）；连续失败熔断，降级为「仅存 URL + 标题」并提示用户。

### 4.2 整理（怎么归档）

- **状态流转**：`inbox → filed → archived`，**状态由路径推导**（见 §3.2），移动文件即改状态，无第二事实源
- **AI 辅助**：一键「帮我整理」→ AI 建议目标目录与标签、补全摘要、检测与已有文档的重复；触发方式可选（手动 / 入库后自动 / 定时）
- **手动整理**：GUI 里拖动/移动、改标签、编辑正文与元数据、批量归档收集箱
- **回收站**：删除进入 `.trash/` 暂存，可恢复或彻底清除，避免误删；agent 的 `kb_delete` 只能进回收站，不允许直接删除
- **agent 操作断路器**：agent 批量操作（一次 >5 篇，可配置）需用户确认后执行，防一次误推理批量改写
- **定期维护**：提醒过期内容、清理收集箱积压

### 4.3 检索（怎么取用，核心能力）

三级检索，从快到深：

1. **关键词全文检索**（即时、离线）：Host 端**内存倒排索引**（字符 2-gram，覆盖中文、免分词库）增量更新，命中按**分字段加权 BM25** 排序（标题/别名/标签权重高于正文）；部分命中仍返回排序结果，且容忍单字符错别字。匹配标题 + 别名 + 摘要 + 标签 + 正文。支持轻量语法：`tag:AI`、`path:10-技术`、`status:inbox`、`title:关键词`，多词空格为 AND（BM25 下退化为加权 OR 召回）。
2. **AI 引用式检索**（日常问答场景）：用户提问时，智能体自动先查知识库；命中则把相关文档作为参考注入回答，并标注引用（`[来源: 文档名]`）；未命中再走网页搜索。注入有预算控制：默认取 top 5 篇、每篇截取摘要+首段（可配置），避免撑爆上下文。
3. **语义检索**（Phase 3 增强）：向量嵌入 + 相似度搜索，解决「说法不同但意思相同」的匹配问题。

### 4.4 知识库入口（怎么进入）

设计原则：**两步可达** —— 从任意界面两步内打开知识库，且不打断当前对话。

| 入口 | 位置 | 说明 |
|---|---|---|
| 主入口 | 侧栏底部「知识库」按钮（设置按钮旁） | 全局常驻，任何会话/页面可见；点击以浮层方式弹出知识库面板 |
| 快捷入口 | 会话头部右上角知识库图标 | 当前会话内一键打开/收起面板 |
| 辅助入口 | 对话中直接说「打开知识库 / 看看知识库里……」 | 智能体检索知识库时，可同时弹开面板定位到相关文档 |

面板形态：**浮层（overlay）**，不离开当前会话 —— 左侧目录树/标签，中间文档列表/预览，右侧/下半区编辑器；可开关、可缩放，关闭即回到对话。浮层内操作全部走本地 RPC，与聊天上下文互不干扰。

> 已对照当前 GUI 实际插槽验证：主入口挂 `sidebar.footer.action`（侧栏底部动作位，可追加）、快捷入口挂 `conversation.session.header.utilities`（会话头部工具位，可追加）、面板渲染在 `shell.overlay`（全局浮层位）—— 均为可追加列表位，不改动出厂界面。

### 4.5 GUI 知识库面板

| 区域 | 功能 |
|---|---|
| 搜索框 | 全文检索，即时结果 |
| 目录树 / 标签 | 按目录、标签、状态过滤浏览 |
| 文档列表 | 标题、摘要、时间、状态 |
| 文档视图 | 分屏编辑（源码 + 实时预览）+ 元数据编辑 + 反向链接列表 |
| 操作 | 新建 / 移动 / 删除（进回收站）/ 复制引用（`[[文档名]]`） |

### 4.6 文档编辑与保存

**编辑器选型**（已调研主流轻量方案）：

| 方案 | 体积 / 特点 | 适配性 |
|---|---|---|
| **自研：textarea + 轻量预览（推荐 MVP）** | 零依赖、零网络请求、始终可用；分屏实时预览，覆盖标题/列表/引用/代码块/表格/链接等常用语法 | ✅ 本插件 Client 环境是纯 React + RPC，无打包器，外部库只能经 CDN 引入，受 CSP 与网络影响 |
| Cherry Markdown（腾讯开源） | 功能全：分屏 / 所见即所得 / 源码三模式，中文生态好，可扩展 | ⚠️ 需 CDN 引入；Phase 2 评估（见其[竞品分析](https://github.com/Tencent/cherry-markdown/wiki/%E7%AB%9E%E5%93%81%E5%88%86%E6%9E%90-%E7%94%B1-urlyy-%E8%B4%A1%E7%8C%AE)） |
| EasyMDE / [overtype](https://github.com/panphora/overtype) | 极轻（几十 KB），textarea 增强 + 实时预览；overtype 理念「就是个 textarea」与本方案最接近 | ⚠️ 同上，需 CDN 引入 |
| Milkdown / Vditor / ByteMD / CodeMirror 6 | 现代、功能全但依赖重或需构建打包 | ❌ 不适合无打包器的动态插件环境（CodeMirror 选型分析见[这里](https://www.chatdlm.com/docs/20260416-bian-ji-qi-xuan-xing.html)） |

结论：**MVP 采用零依赖方案** —— Markdown 源码编辑 + 分屏实时预览（内置轻量渲染，纯 React 实现，无外部请求）。若后续需要完整 GFM / 所见即所得，再验证 CSP 后以 CDN 方式引入 Cherry Markdown 等（Phase 2 可选）。

**保存机制**：

- **自动保存**：停止输入 0.8 秒后自动保存（防抖），`Ctrl/Cmd+S` 立即保存；保存状态实时显示：未保存 ● / 保存中 / 已保存 ✓ / 失败可重试
- **保存链路**：编辑器 → `host.call('kb.saveDoc')` → Host 原子写盘（先写临时文件再替换，防止写一半损坏）→ 同步更新 frontmatter（`updated` 时间）与索引
- **新建文档**：面板「新建」→ 输入标题（可选模板：普通笔记 / 读书笔记 / 会议纪要 / 代码片段）→ 按模板生成 frontmatter 骨架 → 落到当前目录（默认收集箱），新文档同样可编辑可保存；模板库在 `kb/templates/`
- **冲突保护**：打开文档时记录 `expectVersion`（mtime+size 哈希）；每次保存（含 agent `kb_update`）经 Host 校验版本，不匹配返回冲突 —— GUI 提示合并/重载，agent 重读后重试，杜绝静默覆盖（协议见 §3.4）
- **可恢复**：`kb/` 纳入 git 后，误改误删可回滚历史版本

### 4.7 图片支持（![[路径]] 嵌入 / 粘贴 / 解析 / 存储）

**引用语法**：统一采用 **wiki 嵌入 `![[路径]]`**（Obsidian / 思源笔记风格，与主流知识库工具生态兼容、便于迁移互导）；`|` 后为说明文字（alt）。同时兼容标准 Markdown `![alt](路径)`（网页剪藏与导入的旧文档仍能正常显示），**新写入一律用 `![[...]]`**。

| 来源 | 写法示例 | 解析规则 | 预览方式 |
|---|---|---|---|
| 远程 URL | `![[https://example.com/a.png]]` | 识别 `http(s)://` 前缀，直接使用原 URL | 联网直接显示；提供「下载到本地」一键转为本地引用（离线可用） |
| 相对路径 | `![[2026-01-05-rag.assets/diagram.png]]` | 含 `/` 时：先相对**文档所在目录**解析，未命中再相对**知识库根目录** | Host 读取图片 → base64 data URL 渲染 |
| 纯文件名 | `![[diagram.png]]` | 全库按文件名查找（查 `_meta/images.json`）：唯一直接使用；重名优先文档同目录，仍歧义则提示选择 | 同上 |

说明文字示例：`![[diagram.png|架构图]]`（`|` 后为 alt，可省略）。

> 知识库外的本地绝对路径（`D:\...`、`C:/...`）与 `file://` 无法在浏览器页面直接渲染，MVP 不引用，提示先导入知识库。

**图片存储**：

- 默认存放：**文档旁的 assets 目录**（`<文档名>.assets/`）—— 文档与配图同目录，整体移动/搬运不失效
- 粘贴图片时弹出轻量选择器，可**选择目标目录**：当前文档 assets（默认）/ 全局图片库 `kb/_assets/` / 其他目录；文件名默认时间戳，重名自动加后缀（`2026-01-05-1453-2.png`）
- 远程图片：粘贴 URL 时可选「仅引用原 URL」或「下载到本地」
- 索引：`_meta/images.json` 维护全库图片清单（文件名 → 路径 + 引用关系，扫描重建），支撑 `![[文件名]]` 直查与反向引用

**粘贴/插入流程**：

1. 粘贴图片（Ctrl+V 剪贴板图片）或拖入 / 选择图片文件
2. 选择器确认：目标目录 + 文件名（默认值已填，可改）
3. Client 读取图片 → base64 经 `host.call('kb.saveImage')` 传给 Host
4. Host 写入目标目录 → 返回最终相对路径
5. 编辑器光标处自动插入 `![[相对路径]]`（默认带文档相对路径，无歧义；可手动精简为 `![[文件名]]` 走直查）

**技术要点**：

- **wiki 嵌入解析**：渲染器同时识别 `![[...]]`（新语法）与标准 `![...](...)`（兼容旧内容）；解析规则见上表，找不到图片时显示占位并提示路径，不中断预览
- **预览渲染**：本地图片由 Host 读取后以 base64 data URL 返回，不依赖静态文件路由、离线可用；Client 按「路径+mtime」做 LRU 缓存，同会话不重复请求；若后续验证 GUI 已有工作区静态路由，则改用 URL 直连
- **二进制传输**：Client→Host RPC 是 JSON，图片以 base64 编码传输；单图 >10MB 拒绝并提示压缩，>1MB 分块传输避免阻塞 RPC 通道；剪贴板/文件读取依赖浏览器标准 File API（页面环境通常可用，实现时验证；若受限则降级为粘贴图片路径/URL 文本）
- **反向引用**：`images.json` 记录每张图片被哪些文档引用；移动/删除文档时提示引用关系，避免误删仍在使用的图片
- **大图处理**：MVP 原样存储；Phase 2 增加粘贴时可选压缩与缩略图
- **清理**：删除文档时提示是否一并删除其 assets 目录；孤儿图片检测放 Phase 2
- 图片内容不进全文检索（MVP），Phase 3 可评估 OCR / 图像向量化

### 4.8 文档互链（双链）

与 `![[图片]]` 同源，文档之间用 `[[文档名]]` 建立链接，形成知识网络：

- **语法**：`[[文档名]]` 链接到库内文档；`[[文档名|显示文字]]` 自定义显示文字；`[[文档名#标题]]` 定位到文档内章节
- **解析**：按文件名直查（查 `_meta/index.json` 文档清单），规则同图片：唯一直接命中，重名优先同目录，仍歧义提示选择；链接失效（文档不存在）显示灰色占位并提示；agent 场景无法交互选择，按确定性规则取「同目录 → 目录浅 → 最近修改」并记录警告
- **反向链接**：文档详情展示「被哪些文档引用」（backlinks），支持顺藤摸瓜
- **面板**：文档视图下方列出出链 / 反链；搜索结果、目录树中双链文档可一键跳转
- **Phase 2 增强**：悬停预览文档内容、知识关系图（力导图）

### 4.9 可配置项（Config）

所有可调参数集中为插件配置，不硬编码（符合 DSH 约定）：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `kb.rootDir` | `<工作区>/kb` | 知识库根目录 |
| `save.debounceMs` | 800 | 自动保存防抖延迟（毫秒） |
| `search.topK` | 5 | AI 引用式检索注入的文档数上限 |
| `search.autoInject` | true | 提问时是否自动检索知识库 |
| `search.bodyLimit` | 每篇首 2000 字 | 注入正文截断长度 |
| `collect.autoMeta` | true | 入库时自动拟标题/摘要/来源 |
| `images.assetsDir` | 文档旁 `<名>.assets/` | 图片默认存放目录 |
| `images.maxSizeMb` | 10 | 单图大小硬上限，超出拒绝并提示压缩 |
| `agent.batchConfirmN` | 5 | agent 批量操作超过该篇数需用户确认 |
| `fetch.timeoutMs` / `retry` / `maxBodyMb` | 10000 / 2 / 5 | URL 剪藏护栏（见 §4.1） |
| `organize.maxDocsPerRun` | 20 | kb_organize 单次处理上限（Phase 2） |
| `search.telemetry` | true | 记录注入命中率与 token 消耗 |

### 4.10 成本与遥测（FinOps）

- **注入遥测**：记录每次自动检索注入的命中率与 token 消耗，用数据校准 `search.topK` / `search.bodyLimit` 默认值，而非拍脑袋常量
- **整理成本熔断**：`kb_organize` 单次运行受 `organize.maxDocsPerRun` 上限 + 逐篇成本日志约束，超限即停
- **语义检索成本**（Phase 3）：embedding 本地小模型优先（如 bge-small-zh），避免每次入库都付 API 费用。**模型获取零手工安装**：首次启用自动下载到 `_meta/models/` 缓存（需一次性联网，百 MB 级），之后全离线、0 元/次；下载失败或离线环境自动降级为关键词检索；纯离线场景可手动放置模型文件（仅解压拷贝，无需安装运行环境）。实现通道：Host 插件为受限纯 JS，经 `ctx.subprocess` 调用 embedding helper 进程负责下载与推理

## 5. 智能体协作流程

```
用户提问
  │
  ▼
① 自动检索知识库（kb_search）
  │
  ├─ 命中 → 注入相关文档作为参考 → 作答 + 标注引用
  │
  └─ 未命中 → 网页搜索 → 作答
              └→ 询问「要把这条存进知识库吗？」→ kb_add
```

日常用法示例：

- 「存一下：RAG 的核心是检索 + 生成两阶段」→ 一句话笔记入库
- 「结合知识库里存过的内容，帮我写一份技术选型对比」→ 自动引用历史知识作答
- 「知识库里有哪些关于部署的内容？」→ 列出相关文档

**知识库工具职责表**（接口按职责划分，避免长成「万能接口」）：

| 工具 | 职责 | 关键参数 |
|---|---|---|
| `kb_search` | 检索（含语法过滤） | 关键词、过滤器、topK |
| `kb_add` | 新建文档 | 标题、正文、目录、标签、来源 |
| `kb_get` | 读取文档 | docId |
| `kb_update` | 改正文或元数据字段（不改路径） | docId、expectVersion、变更字段 |
| `kb_move` | 移动/重命名（移动即改 status） | docId、目标目录 |
| `kb_delete` | 删除（只能进回收站） | docId |
| `kb_organize` | AI 整理（Phase 2） | 范围、maxDocsPerRun |

## 7. 安全防护与数据备份

**防护（P0，实施于 1a / 1b）**：

- **路径沙箱**：所有文件操作（含 agent 工具）先 `resolve` 再强制校验落在 `kb.rootDir` 之内，拒绝 `../` 穿越与符号链接逃逸 —— 防 prompt injection 诱导任意文件读写
- **渲染 sanitize**：预览渲染一律文本转义优先，不支持内嵌 HTML（或严格白名单）；图片 src 仅允许 http(s) 与 Host 生成的 data URL
- **外部请求护栏**：URL 剪藏的超时/重试/大小/协议四上限 + SSRF 防护（见 §4.1）
- **agent 权限**：`kb_delete` 只能进回收站；批量操作需确认（见 §4.2）

**备份**：

- **纯文件存储**：复制、压缩 `kb/` 目录即完成备份；推荐用 git 做版本管理
- **无外部依赖**：不依赖数据库，索引丢失可扫描重建
- **路径可配置**：知识库根目录可通过配置指向任意位置
- **敏感内容**：导出/分享前可用可选检查扫描（Phase 2）；公开共享前自行确认

## 8. 关键权衡与风险

| 风险/权衡 | 应对 |
|---|---|
| 动态插件不跨进程重启 | 数据在磁盘上不受影响；重新激活即可。Phase 3 做成 preset 常驻 |
| 关键词检索不理解语义 | 先保证即时可靠；Phase 3 引入向量语义检索 |
| 文档量大后全文搜索变慢 | 内存倒排索引（2-gram）替代线性扫描；>5000 篇索引分片 |
| 中文分词精度 | 2-gram 字符索引天然免分词；后续可引入轻量分词提升精度 |
| 重复内容堆积 | `kb_organize` 去重检测 + 状态流转机制 |
| 双链/反链随文档增长计算变慢 | 出链/反链在索引中预计算（`index.json` 存链接图），打开时直接读取 |
| 索引单文件写放大 | schemaVersion + 原子替换 + 启动校验自动重建；分片按阈值触发 |
| 双通道写冲突（GUI/agent 静默覆盖） | expectVersion 乐观锁统一写路径，冲突显式处理 |
