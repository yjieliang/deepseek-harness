# 知识库双引擎收敛实施方案

> 目标：消除 [[2026-08-15-知识库整体设计评估与优化建议]] §3.1 的双实现漂移。方法以 **harness 自身的设计理念**为主轴，而不是以「用户目录里那份 import-free mjs」的现状为起点 —— 正确的收敛不是二选一，而是把漂移的临时实现**溶解回 harness 的正规形态**。

## 1. 设计理念对齐（每条决策都从理念推导）

| harness 理念 | 本设计的落地 |
|---|---|
| 一切皆插件；能力 = Service Definition / Provider / Consumer 三方 | 知识库也是一个 seam：`ctx.kb` 服务（引擎）+ 两个 Consumer（Remote 网关、tool 工具包） |
| 双平面：host 装注册表与跨会话服务；preset 装单会话的工具/人设/提示词 | 引擎、Remote 网关、图片路由 = **host**（进程级单例）；`kb_*` 工具 = **agent preset**（按会话 opt-in） |
| 发布服务的行必须留在 host 组合（realm 规则） | `ctx.kb` 服务只能由 host 组合提供（web-app patch 已挂 `dsh-host-kb`） |
| preset 只组合行，绝不持有实现 | `knowledge-base` preset 收缩为一行 `dsh-tool-kb` + 提示词段；700 行 mjs 删除 |
| 工具是一等 package（`@deepseek-ai/dsh-tool-*`，`name/inject/Config/apply` + 测试 + README） | 新增 `@deepseek-ai/dsh-tool-kb`，与 `dsh-tool-bash`/`dsh-tool-fs`/`dsh-tool-web` 同构 |
| 部署可变参数一律走 Config，不硬编码 | search 默认 topK、批量确认阈值、归档天数、剪藏护栏等收进 schemastery Config |
| 模型可见 ⟺ 可入日志；工具 render 属设计的一部分 | 工具 schema/output render、README Model Experience 按 tool-* 规范落实 |

参考范式：`fs` seam —— `packages/fs/fs`（Service Definition，`class FileSystem extends Service` 默认导出、`declare module` 声明 `ctx.fs`）→ `packages/fs/fs-local`（Provider，`class LocalFileSystem extends FileSystem`）→ `packages/fs/tool-fs`（Consumer，函数插件）。kb 复用同一骨架。

## 2. 决策：保留哪个引擎

**保留 host 引擎，重塑为 `ctx.kb` 服务；删除 preset 的引擎副本与全部实现代码。**

这不是「host 更好所以留 host」的直觉取舍，而是按设计理念归位：

- host 引擎是 typed + 单测 + 可配置 archiveDir + 含 01-inbox + 带回收站清扫的完整实现，且它本就该是 host 平面的共享服务（同 `fs`，进程单例、键不由会话决定）。
- preset 引擎副本是 ESM 受限下的权宜拷贝，已漂移 7 处；它在「preset 里写实现」这件事上同时违背了 seam 三方（缺 Service Definition 与 tool Consumer 包）与「preset 只组合」两条理念。
- 因此决策的实质是：**引擎留在 host 并升级为 Service；工具从 preset 提升为一等 Consumer 包；preset 清空实现、只做组合。**

## 3. 目标架构

```
packages/host/kb（host 平面）
  KbLibrary  (class KbLibrary extends Service，declare ctx.kb)   ← 唯一读写 kb/ 与 _meta/* 的实现
       ▲ provide（web-app cordis.patch.yml 挂 dsh-host-kb）
       ├── KbGateway   (inject: [fs, kb])  Remote kb.* 18 方法 + /dsh-kb 图片路由   → 面板
       └── 供 agent 平面经 ctx.kb 消费

packages/host/tool-kb   @deepseek-ai/dsh-tool-kb（agent 平面，函数插件）
       inject: [tools, kb, systemPrompt, web]
       注册 15 个 kb_* 工具；复合工具（archive/organize/import/export/clip）组合 ctx.kb 原语

knowledge-base preset（~/.dsh/.agent-presets/knowledge-base/）
       agent.cordis.yml 一行：- id: kb-tools / name: '@deepseek-ai/dsh-tool-kb'  + 提示词段
       删除 kb.plugin.mjs
```

| 角色 | 包 | 平面 | 挂载位置 |
|---|---|---|---|
| KbLibrary 服务 | packages/host/kb | host | web-app cordis.patch.yml（现有 `kb` 行） |
| KbGateway（Remote + 图片路由） | packages/host/kb | host | 同上 |
| tool-kb（15 工具） | packages/host/tool-kb | agent preset | `knowledge-base` preset 的 agent.cordis.yml |

> 目录前缀不决定平面：`packages/fs/tool-fs` 与 `packages/web/tool-web` 都是 agent 平面工具，却与其 capability 服务同组。kb 服务在 `host/` 组，工具 Consumer 落 `host/tool-kb`，由「哪份组合挂载它」决定平面，而非目录名。

## 4. KbLibrary 服务面（映射 18 个 Remote 方法 + 15 个工具）

| 服务方法 | 覆盖 | 本次顺带处理 |
|---|---|---|
| search({query, status?, tag?, directory?, topK}) | kb_search / kb.search | 字段语法 `tag:/path:/status:/title:` 落到引擎；补齐 title 过滤 |
| list / get / save / create / move / remove / restore / purge | 对应工具与 Remote | save 捕获 `FS_STALE_VERSION` 返回 `conflict: true`（修死字段）；get 补 `outLinks` |
| resolve / dirs / stats / tags / refresh / createDir / renameDir / trash | 对应工具与 Remote | 现状保持 |
| links(path) | kb_links | 新增（outLinks + backlinks） |
| images() | kb_images | 并入引擎：扫描/重建 images.json/列孤儿；统一 images.json 为对象格式 |

复合工具（留在 tool-kb 包，组合原语）：archive（list+move、dry-run 门）、organize（list 之上启发式）、import（create 循环）、export（get 循环）、clip（web fetch + create）。

## 5. 实施步骤（6 阶段，各自可验收）

### 阶段 1 —— 引擎升格为 Service

- `packages/host/kb`：`KbEngine` 重构为 `class KbLibrary extends Service`，默认导出；`declare module '@deepseek-ai/cordis'` 声明 `ctx.kb`；补齐 §4 能力（outlinks / images / 字段过滤 / conflict）。
- **验收**：`KbLibrary` 作为服务行可被 Loader 实例化提供；service.spec.ts 覆盖新增能力；core.spec.ts 保持绿。

### 阶段 2 —— 网关降为 Consumer

- `KbGateway` 改 `inject: ['fs', 'kb']`（extends TypertRemoteService 保留 Remote 命名空间）；18 个 `@Remote` 方法体改为 `ctx.kb.x()`，只做 wire 边界与 AbortSignal 透传；图片路由读 `ctx.kb.image()`。
- **验收**：面板 wire 契约零改动；`test:gui`（含 ui-kb 面板用例）绿。

### 阶段 3 —— 新建 tool-kb Consumer 包

- `packages/host/tool-kb`（`@deepseek-ai/dsh-tool-kb`）：函数插件 `name: 'tool-kb'`、`inject: ['tools', 'kb', 'systemPrompt', 'web']`、schemastery `Config`（search 默认 topK、批量确认 N、归档天数、剪藏护栏四参数等——不硬编码）、`apply` 注册 15 个工具 + 提示词段。
- 从 mjs 迁移 15 个工具到 typed 实现；复合工具改为组合 `ctx.kb` 原语（`ctx.get('web')` 供 clip，保留服务缺失时的清晰报错）。
- **验收**：单测（tools.spec.ts）+ invariant 伴生 + README（Model Experience 段）。

### 阶段 4 —— preset 收缩为纯组合

- `knowledge-base` preset：删除 `kb.plugin.mjs`；`agent.cordis.yml` 把 `kb-tools` 行改为 `name: '@deepseek-ai/dsh-tool-kb'`（去掉 `./kb.plugin.mjs`）；提示词段移到 tool-kb 包内（或留一行注入）；`preset.yml` 描述同步。
- **验收**：preset 目录只含 `agent.cordis.yml` + `preset.yml`，无实现文件；`ctx.get('kb')` 经平台服务注入，不 import 任何 harness 包。

### 阶段 5 —— 解析与依赖登记

- 组合行 `name: '@deepseek-ai/dsh-tool-kb'` 走 Loader 的包名解析（同 standard preset 引 `dsh-tool-bash`），与旧 mjs 里「模块入口 `import` 走 Node ESM」不是一回事。把 `@deepseek-ai/dsh-tool-kb` 登记进它要挂载的部署依赖（`packages/bundle/web-app/package.json` 的 dependencies；`tool-kb` 行纳入 web-app 或 profiles 解析清单）。
- **验收**：`ctx.agentPresets.standingKeyFor('knowledge-base')` 挂载校验通过（不报「Cannot find package / 未激活 / 进程级服务」），再交给用户真实会话确认工具清单。

### 阶段 6 —— 清理、回归、文档

- 逐项回归 §3.1 七处漂移（01-inbox、archiveDir、images.json、重复 updated、排序、index.json 单写者、refresh）。README 的「Index duplication with the preset」限制改为已解决并补 KbLibrary 契约。
- `pnpm run typecheck`、`pnpm run test`（kb/tool-kb）、`pnpm run lint`；按仓库约定，落地时同 PR 附 Agent Note。

## 6. 风险与回滚

1. **服务缺失降级**：tool-kb 用 `ctx.get('kb')`（非硬 `inject`）读服务，宿主未挂 kb 时工具报「知识库服务未挂载」而非让整个插件卡在注入等待——沿用 kb_clip 对 web 的既有退化模式。
2. **单写者收敛**：index.json / images.json 改由 `ctx.kb` 独占，消除双写竞争；迁移期旧 mjs 与 engine 并存时仍会写 index.json，阶段 4 删除副本后彻底消除，期间以 `ctx.kb` 的最后写入为准。
3. **回滚**：阶段 1/2 是纯新生委托（面板契约不变）；阶段 3 是新增包（可整体不挂）；阶段 4 改动的是用户 preset，可整体恢复旧 mjs 目录。kb/ 数据格式不变，schemaVersion 仍为 3。
4. **不扩大范围**：P1 相关度排序/单字符降级/命中高亮/增量子刷新/批量确认门、P2 全部，不在本方案内（见 [[2026-08-15-知识库整体设计评估与优化建议]] §4）；阶段 1/3 只顺带做与收敛强相关的字段语法、conflict、images 格式、配置纪律。

## 7. 验收标准（总）

- 全库只存在 `ctx.kb` 一份引擎实现；preset 无任何索引/磁盘/状态推导/工具实现代码。
- 双通道（面板 + agent）对文档状态、排序、归档目录、图片、回收站行为逐项一致。
- 15 个 `kb_*` 工具作为 `@deepseek-ai/dsh-tool-kb` 一等包工作；服务缺失时报错清晰且不拖垮 preset。
- `standingKeyFor('knowledge-base')` 挂载校验通过；host/kb + tool-kb 单测、`test:gui`、typecheck、lint 通过；面板 wire 契约零改动。
