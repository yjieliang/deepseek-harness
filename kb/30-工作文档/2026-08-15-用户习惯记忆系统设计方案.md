# 用户习惯记忆系统设计方案

> 目标:让用户高效地自定义"记忆习惯"(偏好、规范、工作约定),稳定作用于 agent 的每次会话。
> 硬指标:**效率**(定义成本低、注入 token 省、生效快)与**稳定**(跨会话持久、并发安全、可审计、防污染)。
> 设计原则:**harness 设计理念优先** —— 能力接缝三角色、模型可见⟺已记录、扩展点而非循环变更、执法在决定处、显式>隐式、全 Config、提交点发布。

---

## 1. 能力接缝:habits seam 三角色

| 角色 | 包 | 职责 |
|---|---|---|
| **Service Definition** | `dsh-user-habits` | `HabitStore` 契约、类型、错误码、`user-habits/committed` 事件 |
| **Service Provider** | `habits-settings-backend` | L1 全局层:settings namespace `user-habits` |
| **Service Provider** | `habits-file-backend` | L2 项目层:工作区 `USER.md` 原子写 |
| **Consumer** | `dsh-tool-memory` | 模型面工具:add/propose/list/remove |
| **Consumer** | `dsh-command-memory` | 人面命令:`/memory` |
| **Consumer** | 常驻注入器 | system-prompt section(L1)+ agent-inject 文件链(L2) |

消费者只认契约不认后端;换后端(如未来外部记忆服务)产品不动。

---

## 2. 数据模型

```
HabitEntry = {
  id:        HabitId         # Branded, 不裸 string
  layer:     'global' | 'project'
  topic:     string          # 主题键:style | lang | commit | ...
  value:     string          # 精炼文本(≤ maxEntryChars, 默认 200 chars)
  source:    'user' | 'agent-proposed'   # 最终来源永远是"用户确认"
  version:   number          # CAS 乐观锁(L1);L2 由文件 digest 承担
  updatedAt: number
  expiresAt?: number         # 可选时效("本月用 X"场景;默认无)
}
```

**层语义**(调研印证:Claude Code 层级文件 + LangMem profiles 独立建模):
- L1 global:跨项目、跨会话(回复语言、代码风格、工具偏好)
- L2 project:单项目、跨会话(技术栈、命名规范、PR 约定)
- 会话级一次性约束不落长期记忆(会话日志内解决)

**USER.md 定位声明**:L2 是**个人习惯文件**,建议 `.gitignore`、不提交进仓库;团队共享规范走 `AGENTS.md`,两者职责不重叠。

### 文件 ↔ 条目映射约定(file backend 的地基)

- 文件内一个 `## <topic>` 小节 = 一条条目;小节正文 = value
- 条目 `id` 由 `topic` 派生(内容寻址),人编辑文件 = 更新条目,版本由文件 SHA-1 digest 承担
- **解析失败的段落原样保留为"未解析区"并大声报出**,不猜、不丢、不静默吞掉

## 3. 读写契约(多 backend 路由语义)

| 操作 | 语义 |
|---|---|
| `write(entry)` | 按 `entry.layer` 路由到对应 backend;守卫在契约层执行,与后端无关 |
| `remove(id)` | 按 id 全局查两层,查到哪层删哪层 |
| `list()` | 合并两层,返回时标注每条的 layer 与来源 |
| 就近覆盖 | 渲染层执行:L1 section 的 text provider 读 `AssembleContext.agent.session.header.cwd` 取该 cwd 的 L2 条目,同 topic 时 L2 覆盖 L1;写入层允许并存,渲染结果标注来源层 |

## 4. 写入路径与守卫(执法在决定处)

```
写入口(HabitStore.write —— 守卫内建于此,所有消费者必经,不可绕过)
  │
  ├─ Unicode 归一化(NFKC + 隐形字符检测)      → guard-injection
  ├─ 指令注入模式检测                          → guard-injection
  ├─ 敏感信息检测(密钥/高熵/密码模式)          → guard-secret
  ├─ 预算硬上限(单条字符 + 层 token)            → over-budget
  └─ 确定性合并:
       同 topic 已存在 → 强制 update,拒绝 add    → topic-exists
       value 归一化后重复 → 拒绝                → duplicate
       子串定位歧义 → 列出候选、不猜             → ambiguous
  │
  ▼
持久化(settings CAS 写 / USER.md 锁内重读→改→temp→原子替换)
  │
  ▼
user-habits/committed 事件(仅在持久化成功后发出)
```

- **守卫分层策略**:`agent-proposed` 来源的违规**硬拒绝、不可放行**;`user` 来源的违规**警告 + 用户二次确认后可覆盖**(人类是最终闸门,但必须知情)
- **预算测量**:单条用字符数(`maxEntryChars`);层 token 预算用 `ctx.tokenMeter` 估算
- **remove 不守卫**(不引入新内容),只有 add/replace 的 value 过守卫
- **确定性合并优先**:LLM 语义比对("两条说的是一回事")是 opt-in(`llmConsolidate`),启用时合并调用走 `ctx.llm`,失败自动降级为确定性规则
- **CAS 重试策略**:工具写前先读(list 返回即带 revision);冲突返回 `conflict` 后由 agent 决定重试,工具不做自动重试循环
- **L2 并发编辑**:写前锁内重读,digest 不符则重读合并后再写;仍冲突(人正在编辑)返回 `conflict`,不覆盖用户未保存内容;写 temp 命名带 session 标记,启动时清理孤儿 temp

两条写入路径共享同一写入口:
- **路径 A 用户自定义**:`/memory` 命令 / 设置表单 / 直接编辑 `USER.md`
- **路径 B 半自动**:agent 观察 → `memory_propose(topic, value, 依据)` → 守卫 → `userQuestions.ask()`(`[记住][忽略]`,detail 提示"想调整?选「忽略」后直接说要记住什么")→ 采纳走与 A 相同的写入口;忽略记 rejected

### 来源判定与回显(确定性优先)

- **来源由工具名确定**:`memory_add` = 用户要求的写入(source=user);`memory_propose` = agent 主动建议(source=agent-proposed)。不靠内容猜来源。
- **topic 由模型调用时填参**(调工具的就是模型,不存在二次 LLM 提取);topic 空则落 `general`
- **回显 = 写入后告知,非写入前确认**:`memory_add` 结果带"已记住:[topic] value",模型转述给用户;用户不满意一句话覆盖(同 topic replace 成本极低)。写入前确认会打断,砍掉
- 弹窗为两选项制:userQuestions 是选项协议,无自由文本输入,"记住但修改"无法在同一弹窗完成,由 detail 提示引导用户走 memory_add

- **提议去重**:内容哈希存 storage-domain,TTL 后失效(`proposalDedupTtlMs`);提议是会话级事实,用户不回答即随会话结束失效
- **弹窗选项措辞是模型可见契约**:`[记住][忽略][记住但修改]` 等 label 作为 userQuestions 选择值进入 tool/result 与模型上下文,措辞必须快照 pin,不随意改动

## 5. 注入装配(模型可见 ⟺ 已记录)

| 层 | 方式 | 预算 | 日志重建链 |
|---|---|---|---|
| L1 全局 | 常驻 system-prompt section | ≤ `residentTokenBudget`(默认 600 tokens,经 tokenMeter 估算) | `request/header` 快照 |
| L2 项目 | 常驻 durable user-role 注入 | agent-instructions `maxBytes` 预算 | 带 typed source + digest 的 `user/message` |
| 细节/低频 | 按需检索 | 不占常驻 | `kb_search` 的 `tool/call` + `tool/result` |

效率要点:
1. **常驻 vs 按需二分**(= Letta core vs archival block):高频短习惯常驻,细节进 kb 按需召回
2. **固定顺序 + 固定结构**:section name/order 恒定、条目按稳定 id 排序 → 改一条习惯只变一处文本,前缀 KV cache 复用不被破坏
3. **L2 增量刷新**:复用 agent-instructions 的 SHA-1 digest 去重、tombstone、compaction 后再注入全套机制
4. **截断优先级**:习惯条目要么完整注入、要么整条省略,绝不做字节级截断;省略时发出可见通知

**回放一致性原则**:重建模型历史读 `request/header` 快照与已记录的 `user/message`,**不重新渲染**——settings/文件当时状态不可重建,快照才是权威。

职责边界:**habits 只承载偏好/约定条目;知识进 kb,检索直接用 `kb_search`,不新造检索工具**(one home per fact)。

## 6. 稳定保障

| 保障 | 机制 |
|---|---|
| 并发安全 | L1:settings `expectedRevision` 乐观锁,冲突报 `HabitErrorCode.conflict`;L2:锁内重读→改→temp→原子替换,digest 校验 |
| 写串行化 | settings 每 namespace 串行;L2 单写者锁 |
| 可审计 | `user-habits/committed(entry, op)` 统一事件流(提交点后发出) |
| 可回滚 | L1:`replace()` 回旧快照;L2:文件可 diff/恢复 |
| 生效可观察 | 注入器订阅统一事件,重建 prompt 段/文件链 |
| 崩溃安全 | 持久化先行、事件随后、内存视图最后;孤儿 temp 启动清理 |
| 授权路径 | L2 写入走 `ctx.fs` 授权路径,不绕过文件沙箱;fs 缺席时写返回 `fs-unavailable`,注入路径 no-op(与 agent-instructions 行为一致) |

## 7. 配置(全部 Config 字段,无硬编码)

| 字段 | 默认 | 说明 |
|---|---|---|
| `maxEntryChars` | 200 | 单条 value 硬上限 |
| `residentTokenBudget` | 600 | L1 常驻注入预算(tokens,经 tokenMeter 估算) |
| `projectFileCandidates` | ['USER.md'] | L2 候选文件名 |
| `proposalDedupTtlMs` | 7d | 被拒提议去重窗口 |
| `userQuestionAsk` | true | 半自动提议是否弹确认 |
| `llmConsolidate` | false | 是否启用 LLM 语义合并(opt-in) |

## 8. 工程要求(harness 强制)

- **注册即效果**:section/工具/settings namespace 注册均返回 disposer,HMR 卸载即消失
- **不变式**:`dsh-user-habits/invariant` —— `user-habits/committed` 事件载荷与 provider 持久化状态一致(检查权威数据流;注入文本一致性由快照测试覆盖)
- **测试**:守卫每拒绝路径有反例;模型可见文本(工具结果、确认弹窗选项、section 渲染)有快照 pin;预算边界测精确限值(恰等于上限、超 1 char);工具包过 Loader 真实组合测试(非手拼 `ctx.plugin`);HMR 安全测试证明 registry 贡献可回收
- **Model Experience 文档**:按规范记录模型看到什么、token 效应、KV cache 效应

## 9. 用户使用设计

### 五个入口,按场景选择

| 入口 | 场景 | 例子 |
|---|---|---|
| 对话直说 | 最常用,想到就说 | "以后回复都用中文"、"记住我喜欢简洁的代码" |
| 确认弹窗 | agent 主动提议时 | "我注意到你总用 camelCase,记住吗?" → [记住] [忽略] |
| `/memory` 命令 | 精确管理 | `/memory add` / `list` / `remove <id>` / `replace` |
| 设置面板 | 批量管理 L1 全局习惯 | 表格编辑、查看预算占用 |
| 直接编辑 `USER.md` | 项目习惯,高级用户 | 编辑器改动自动生效 |

### 三条关键交互规则

1. **显式指令 ≠ 提议,确认时机不同**:用户主动说"记住 X" → 直接写入 + topic 回显;agent 主动提议 → 必弹确认。区分标准:写意图由谁发起。
2. **同 topic 自动合并,记忆不堆积**:后写的覆盖同 topic 旧条目,用户永远看到"一个 topic 一条"的干净列表。
3. **写入即生效 + 预算可见**:下一轮请求即带上,无需重启;`/memory list` 与设置面板显示已用预算/上限。

### 用户旅程

```
① 发现 → ② 确认 → ③ 生效 → ④ 修正 → ⑤ 清理
   │        │         │        │         │
 对话直说  回显/弹窗  下一轮   同 topic   说"删掉那条"
 agent提议  确认      生效     自动覆盖   或 /memory remove
```

### 自定义能力边界

| 能自定义 | 怎么改 |
|---|---|
| 习惯内容 | 五个入口任选 |
| 生效范围 | 写入时指定全局(L1)或当前项目(L2);默认就近覆盖(L2 > L1) |
| agent 提议开关 | Config `userQuestionAsk` |
| 预算上限 | Config `residentTokenBudget` / `maxEntryChars` |
| 审计 | 每条带来源(user / agent-proposed)+ 时间 |

## 10. 模型可见文本契约(逐字,全部可快照 pin)

### L1 常驻 system-prompt section

注册 `{ name: 'user-habits', order: 50 }`(persona 之后、工具引导之前)。无条目时返回空串(整段省略)。

```
## 用户习惯

以下为该用户确认过的偏好。撰写回复时主动遵守;同主题条目以项目级为准。

- [lang] 回复语言:中文
- [style] 偏好简洁的代码风格
```

条目行格式固定 `- [{topic}] {value}`,按条目 id 升序;只渲染生效值(就近覆盖后),模型面不标来源层(来源标注只在人类面 list/面板)。

### 系统提示引导段(order 101)

```
用户习惯工具:
- 用户明确要求记住某项习惯时,调用 memory_add 记录。
- 你观察到用户稳定偏好时,可用 memory_propose 建议记录,由用户确认后再写。
- 未经用户确认的内容不要自动写入习惯。
```

### memory_add(用户直说路径)

Schema:`{ topic?: string, value: string, layer?: 'global'|'project' }`;topic 空落 `general`;layer 空按内容判定。

成功:`已记住:[{topic}] {value}` + `习惯共 {N} 条 / 预算占用约 {X} tokens`;覆盖旧条目时加 `(已覆盖同主题旧条目:{旧value})`。

守卫命中(用户来源,弹 `[仍然记住][算了]` 二次确认):`待确认:该内容包含疑似敏感信息,确认仍要记住吗?`

### memory_propose(半自动路径)

Schema:`{ topic: string, value: string, evidence: string }`。

弹窗:question `要记住这条用户习惯吗?`;detail `[{topic}] {value}\n依据:{evidence}\n想调整内容?选「忽略」后直接说要记住什么。`;options `[记住]` `[忽略]`。

结果文案:
- 采纳:`已记录:[{topic}] {value}`
- 忽略:`未记录,已忽略该建议。`
- 守卫硬拒(agent 来源):`未记录。该建议未通过安全校验(原因:{guard-code}),已拒绝。`
- 重复提议:`未记录。近期已提过相同建议,不再重复询问。`

### memory_list

Schema:`{ layer?: 'global'|'project' }`。输出分层列表 + `共 {N} 条 / 预算占用约 {X} tokens(上限 {Y})`;空列表输出 `(无已记录习惯)`。

### memory_remove

Schema:`{ id: string }`(id 从 memory_list 取)。成功:`已删除:[{topic}] {value}`;未找到:`未找到该条目,先用 memory_list 查看当前条目。`

### L2 注入模板(USER.md)

MVP 复用 agent-instructions 候选链(配置 `projectFileCandidates: ['USER.md']`),沿用其 system-reminder 框架:

```
<system-reminder>
以下为该项目已确认的用户习惯。同主题条目优先于全局习惯。

## commit
Conventional Commits
</system-reminder>
```

### 预算省略通知

L2 条目超预算整条省略时(绝不半条截断):`部分项目习惯因超出注入预算未展示({N} 条)。需要时用 memory_list 查看。`

### /memory 命令输出(人类面)

`/memory list`:分层列表,每行 `- [{topic}] {value}({来源} · {日期})`,末尾预算行 `共 {N} 条 / 预算占用约 {X} tokens(上限 {Y})`。

## 11. 已知边界与开放问题

- **多项目全局视图**:`/memory list` 显示 L1 + 当前项目 L2;跨项目浏览 L2 待后续(设置面板仅管 L1)
- **agent 维度隔离**:Mem0 的 `agent_id` 维度当前单用户单 agent 用不上,标注为未来扩展点
- **隐私**:习惯含个人信息,存 settings.yaml / USER.md 明文;导出/分享前需提示(后续加导出扫描)
- **守卫误报率**:敏感信息/注入检测规则对中文日常用语的误伤率需真实样本调阈值——待 MVP 实测决定
- **外部记忆接入**:语义检索/跨工作区共享是未来需求;DSH 已有 `dsh-mcp-client`,接入路径 = 在 habits seam 增加第 3 个 Provider,不动产品
