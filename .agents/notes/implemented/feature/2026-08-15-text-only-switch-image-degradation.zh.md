# Agent Note: Text-only model switches degrade session images to placeholder text

Status: implemented

[English](2026-08-15-text-only-switch-image-degradation.md) | 中文

## Problem

[多模态图片输入决策](2026-07-22-web-multimodal-image-input-and-durable-attachments.md)把含图会话钉死在支持图片的模型上：只要图片仍在等待发布或存在于会话当前的派生历史中，`session.selectModel` 就拒绝纯文本目标，而两个交付的适配器在图片到达纯文本协议线路时都会以 `UNSUPPORTED_CONTENT` 让请求失败。一张粘贴的截图就足以让会话永远无法切回 `deepseek-v4-flash`；仅有的出路是开新会话、fork 到图片之前，或先压缩掉图片。

拒绝是刻意的——[移除图片块的笔记](../../archived/simplification/2026-07-04-drop-image-content-block.md)把响亮拒绝认可为唯一可接受的不支持姿态，因为它要防的是一种站不住脚的状态：静默丢弃或展平图片。但拒绝混淆了「发送」与「切换」。纯文本模型确实不能接受*新的*图片输入，但它仍能服务会话的*文本*历史——它看不见的图片可以被点名省略，而不是让整个会话不可用。

## Decision

含图会话可以切换到纯文本模型。纯文本协议线路把每个 `ImageBlock` 降级为共享、稳定的占位字符串，而不是让请求失败。

- `IMAGE_OMITTED_PLACEHOLDER` 与 `degradeImages` 位于 `dsh-llm` 的 `content.ts`，与 `contentHasImage` 并列——后者是所有图片策略共享的唯一递归图片遍历。降级把每个图片块替换为占位文本，并以相同方式递归嵌套的工具结果内容；未知的声明合并块原样透传。该字符串是模型可见的，由适配器测试逐字固定，并可作为已记录内容的确定性函数从会话日志重建。
- DeepSeek chat-completions 序列化器在每条消息的任何文本展平路径之前降级一次，因此 user 文本、assistant 文本和工具结果都会输出占位文本。pi-ai 适配器在解析出的模型的模态不含 `image` 时降级请求；支持图片的 pi-ai 路由仍通过附件服务解析持久字节，该处缺少附件服务时仍以 `UNSUPPORTED_CONTENT` 失败。
- `session.selectModel` 不再因图片内容拒绝纯文本目标。当被接受的目标未声明图片输入、且仍有待发布或派生历史中的图片存在时，响应会携带 `imagesDegraded: true` 标记，composer 座位随之以瞬态警告 toast 告知这次降级，因为会话记录仍在渲染模型已看不见的图片。
- 发送时的准入边界不变：向纯文本模型发送*新*图片仍在持久化之前以 `attachment-error` 失败，`read_image` 仍要求路由模型声明图片输入，而来自[原子准入决策](../bug-fix/2026-07-29-atomic-web-image-admission.md)的逐 agent 串行边界仍负责图片准入与模型选择之间的排序——它现在计算的是确切标记而非拒绝。

这不是词表政策所否决的静默丢弃。替换是模型能看见并点名的稳定字符串，用户在切换时被告知，且分歧是单向的：UI 渲染已记录的图片，而模型收到文本。

## Alternatives considered

### 继续拒绝切换

拒绝所防的失败，降级能更精确地防住。其代价是全局性的：含图会话失去对所有纯文本模型的访问，而认可的出路（新会话、fork、压缩）都会丢弃用户想保留的会话上下文。

### 接受切换但在请求时继续失败

比拒绝更糟：选择会生效，随后每一轮都会在同样的历史上失败 `UNSUPPORTED_CONTENT`。选择一旦接受了某条路由，适配器就必须能服务该会话的持久内容。

### 序列化时静默剥离图片

这正是被否决的静默丢弃形态：信息在用户的会话记录与模型的输入之间消失，双方都无迹可循。占位文本让省略对模型显式可见；toast 让它对用户显式可见。

### 切换时自动压缩掉图片

由切换触发的压缩对一个导航动作而言是沉重、有损的副作用，而且甚至不能保证结果：检查点之后保留的尾部仍可能含图，拒绝会在本该解除它的压缩之后继续存在。

## Consequences

- 用户可见的会话记录与模型可见的输入刻意分歧：UI 渲染已记录的图片，而纯文本模型收到占位文本。切换时的 toast 对每次降级选择告知一次；之后没有重复提醒，错过 toast 的用户可能以为模型具备它并不具备的视觉理解。
- 纯文本压缩路由现在可以摘要含图表层：摘要调用同样降级这些图片，因此压缩在先前失败之处得以完成，但检查点丢失摘要模型从未见过的视觉细节。
- `/model` 弹层入口应用降级切换时不显示警告；composer 座位是告知它的界面。
- 修改占位字符串是模型可见变更，由两个包中的适配器测试固定。

## Testing

- `dsh-llm` content 测试固定降级行为（顶层图片、嵌套工具结果递归、未知块透传）。DeepSeek 序列化器测试与一条 pi-ai 适配器测试把占位文本固定在协议上（含嵌套工具结果）；pi-ai 套件保留支持图片路由的附件服务失败。
- apiproxy 套件覆盖持久图片与待发布图片下的带标记接受、无标记的支持图片目标，以及无图切换的无标记情形。客户端 spec 覆盖接受降级切换时的警告 toast，以及失败时不变的拒绝 toast。
- 免密钥组装通道（`apps/web/tests/model-image-degradation.snapshot.ts`）端到端固定产品界面：在携带图片对的 fixture 历史会话上，切换到支持图片的模型没有提示，而切换到纯文本模型被接受并弹出确切的降级 toast。其 fixture 传输层用一份 fixture 本地的模态表镜像宿主的 `imagesDegraded` 标记。
