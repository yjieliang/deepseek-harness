# Agent Note: Knowledge-base BM25 search ranking

Status: implemented

[English](2026-08-15-kb-bm25-search-ranking.md) | 中文

## Problem

知识库的关键词检索要求查询的每个 2-gram 都命中（严格 AND），且结果按置顶／日期排序，因此多词查询漏掉一个词就返回空、结果不按相关度排序，而 2-gram 索引很容易容忍的单字错别字也会让匹配静默消失。

## Decision

引擎的倒排索引从「文档集合」改为「每篇文档的加权词频」，`kb.search` 用分字段加权 BM25 打分（标题 3／别名 2.5／标签 2／摘要 1.5／正文 1）。查询在所有 postings 上累积得分，不再要求 AND 成员关系，因此部分命中的查询仍返回排序结果，命中查询词更多的文档排在前面。没有精确 postings 的查询 gram 会以 0.6 权重扩展到其单字符近邻，从而在不引入拼音表的情况下容忍中英文的单字符错别字。结果顺序为得分、置顶、更新日期。`kb.search` 的线上契约不变，只提升排序与召回。

## Alternatives considered

### 保留严格 AND，只增加相关度决胜

改动最小，但没有解决促使本次工作的召回缺陷：漏一个词的查询仍然返回空。

### 查询侧同义词词典

手工维护的全局同义词表是一个没有当前属主的新可调项；文档级 `aliases` frontmatter 已在需要处提供同样效果，且 BM25 字段权重现在会奖励别名命中。除非召回证据表明需要，否则暂缓。

### 拼音输入容错

需要完整的汉字到拼音映射表（新依赖或数千行）；单字符近邻规则已覆盖错别字容错。若 agent 工作流需要拼音查询，拼音匹配仍是候选。

### Transformers.js + sqlite-vec 语义检索

按设计属 Phase 3；为没有实证召回缺口的个人库引入模型下载、推理、向量存储与阈值调参。`embeddingRef` 索引字段仍为其保留。

## Consequences

- `kb.search` 的 `total` 现在统计全部部分命中而非仅精确 AND 命中，可能大于旧值。
- 倒排索引改为按文档计数；磁盘 `index.json` 格式不变（存的是摘要而非 gram），既有库无需迁移即可加载。
- 模糊近邻扩展会对每个缺失的查询 gram 扫描倒排索引键；个人库规模下没问题，库量级再大时需重访。

## Testing

- 引擎测试（`packages/host/kb/tests/core.spec.ts`）覆盖：标题高于正文的排序、多词部分命中召回、单字符错别字容错、别名高于正文的排序，以及新打分器下仍然通过的既有刷新／列表测试。
